# Build OS — control registry.
#
# One record per consequential control that ALREADY RUNS in this repository.
# One field per line; a blank line separates records; `#` at column 0 is a
# comment. See README.md for the ontology, the licence table, and why this
# format rather than a TSV.
#
# THIS FILE CLASSIFIES; IT DOES NOT RE-AUTHORISE. Where a control exercises more
# authority than its class licenses, the entry says so (`authority_mismatch:
# declared`) and MISMATCHES.md names the line that gates. Changing the authority
# is a governance action and belongs to the operator, not to whoever edits this
# file.
#
# AN ENTRY IS NOT A LINE. Entries are cut at different granularities: some
# classify a single comparison, and `tests.nonvacuity_minimums` classifies a
# family of 34 fitted constants across 12 files. So "20 of 93 declare a
# mismatch" is a fact about this file's granularity, not a count of the
# heuristics that can stop a build — that number is 56, hand-counted in
# MISMATCHES.md's summary table. Quote both or quote the larger one.
#
#   grep -c '^control: '            how many controls are classified
#   grep '^class: C'                how many are heuristics
#   grep -B4 '^runtime_authority: gate'   what can stop a run
#   grep '^authority_mismatch: declared'  what is over-authorised (14 entries)
#
#   # gate on unvalidated evidence — 11 of 93, the sharpest number here:
#   awk -F': ' '/^control: /{c=$2} /^runtime_authority: gate/{g=1} \
#     /^empirical_status: unvalidated/{u=1} /^$/{if(g&&u)print c; g=0; u=0}' \
#     control_registry.txt

notes: HARD TO CLASSIFY, AND THE FIRST ATTEMPT GOT THE ERROR DIRECTION BACKWARDS. Glob disjointness over a KNOWN path set is decidable and would be Class A; that is what the concrete-path pass at line 363 does. But that pass is guarded by `[ -n "$REPO" ]` and REPO defaults to "" (:80), so it does not run unless --repo is given, and even then it iterates paths that ALREADY EXIST — files the agents are about to create, which is the normal fan-out case, are covered by neither pass. The pre-flight pass at line 329 decides whether two globs could ever collide by instantiating each into ONE canonical probe string (`**`->`pdir/pfile`, `*`->`pseg`, `?`->`p`) and testing it against the other's regex. This entry originally called that "a sound-in-one-direction approximation" and offered `a*b` vs `a?c` as the illustration. That is the harmless direction. The real failure is that IT CERTIFIES COLLIDING MANIFESTS AS DISJOINT: `src/*.ts` vs `src/foo*` are passed as disjoint and both match `src/foo.ts`; `*/x.py` vs `app/*` are passed as disjoint and both match `app/x.py`. Two agents are then told they own separate files and they do not. Class stays C, for a changed reason — not "fitted to a sample" but "unsound in the direction that matters". A reviewer could reasonably call this B, and B at gate is a mismatch too, so the entry stays listed either way. The five-class ontology has no slot for "approximate decision procedure with false negatives", which is what this is. Repairing the tool is a separate packet; this entry records.

THE TECHNIQUE IS THE OTHER LIMIT, AND IT WAS UNDER-DISCLOSED — the scope was stated in three places and this was stated in none. `EGRESS_RE` (tests/entitlement_tests.sh:312) is a SYNTACTIC MATCHER over line text: `curl|wget|/dev/tcp|nc|netcat|telnet|https?://|urllib|requests\.(get|post)|socket\.`. Egress that is ASSEMBLED rather than written passes straight through it — a URL or a binary name built up from shell variables, decoded from base64, produced by `$(printf ...)`, or reached through an interpreter this pattern set does not name. So the honest reading of a pass is "no line in these twelve files SPELLS egress in one of these ten shapes", not "these twelve files perform no egress". THIS IS A LIMIT OF RECALL, NOT OF RELEVANCE, which is why the crosswalk binding stays `instantiates`: every line the pattern set matches genuinely IS the prohibited act rather than a stand-in for it, so what the scanner catches, it catches directly; what it misses, it misses silently. REGISTERED SEPARATELY FROM suite.entitlement because it is a security invariant in its own right and not test state: until now the census's only view of it was that suite's RESULT line plus its own vacuity floor, so the registry could see "this scanner is not blind" and could never see "nothing performs egress". That is README section 4's known hole number one — a control added inside an already-registered file — closed here with the live instance that motivated the disclosure.
