# Build OS — governance baseline.
#
# WHAT THIS IS FOR. Registering a NEW control is authorised build work. Moving an
# EXISTING control's class or its runtime authority is a GOVERNANCE act and
# belongs to the operator. Those two are hard to tell apart in a diff of a
# 1500-line stanza file, and "we only added entries" is exactly the sentence
# somebody says while an old entry quietly moved a rung.
#
# So this file pins, for every control that existed at the moment it was written,
# the three fields that constitute a re-authorisation: `class`,
# `runtime_authority`, `authority_mismatch`. tests/mutator_registry_tests.sh
# section 11 requires every id named here to still carry exactly these values.
#
# HOW THE TWO CASES DIFFER, MECHANICALLY:
#   * a NEW control is simply ABSENT from this file, and nothing fails;
#   * an EXISTING control that moves fails, and the only way to make it pass is
#     to edit a line HERE — in a small artefact, in the diff, where a reviewer
#     reads it beside the change that caused it.
#
# It is deliberately redundant with control_registry.txt, for the same reason
# neurocosmology_crosswalk.txt copies class and runtime_authority: two files that
# can be checked against each other detect a drift that one file cannot. WHERE
# THEY DISAGREE, THIS FILE IS NOT THE AUTHORITY — the registry is. This file is
# the record of what the registry said before, and disagreeing with it is a claim
# that needs a reason, not an error in itself.
#
# THIS FILE GRANTS NOTHING AND DEMOTES NOTHING. It creates no control, changes no
# authority and licenses no rung. Every row is a copy.
#
# Written at 7daedee, the base of gravito_p1_mutators_ids_telemetry_a, and
# covering every control registered at that commit. Format, tab-separated:
#
#   control<TAB>class<TAB>runtime_authority<TAB>authority_mismatch
#
