# Build OS — defect classes and their occurrences.
#
# WHAT THIS EXISTS AGAINST. Recurrence was trapped in prose. build-os/memory/residue.md
# carries items (aa)–(ss) in English, and English cannot be counted: a defect that
# has happened once and a defect that has happened five times look identical to a
# reader and identical to a grep. So "this keeps happening" was an impression
# somebody formed by reading, and impressions do not survive a change of reader.
#
# The whole point of this file is that `query(defect_class_id)` returns a NUMBER.
#
# TWO RECORD SHAPES, one field per line, a blank line between records:
#   `defect_class:` — the recurring kind. Stable id, immutable.
#   `occurrence:`   — one instance of that kind, at one time, in one packet.
#
# THE MIGRATION IS DELIBERATELY PARTIAL, AND SAYING SO IS THE HONEST PART. This
# file does NOT normalise residue.md. It seeds the thirteen classes demonstrated in
# the session that produced it, and migrates ENOUGH OCCURRENCES TO PROVE THE QUERY
# — which is a different and much smaller claim than "the history is now
# structured". The classes are real, the occurrences recorded here are real and
# each cites its evidence, and everything else in residue.md is still prose.
#
# THE MIGRATION PATH FOR THE REST, so that "partial" is a plan and not an excuse:
#   1. An item of residue.md maps to an OCCURRENCE, not to a class. Most items are
#      one instance of a class already registered here.
#   2. Give it the next `OCCURRENCE-NNNN` and fill `defect_class_id`,
#      `packet_id` and `evidence_refs` — those three are what make it countable.
#      The rest may be `unknown`; an occurrence with honest gaps beats an
#      occurrence that was not migrated.
#   3. A residue item that fits no registered class needs a new
#      `DEFECT-NNNN-<slug>` FIRST. Do not widen an existing class's meaning to
#      absorb it: a class that absorbs everything counts nothing.
#   4. Leave the prose in residue.md. This file is an index over the history, not
#      a replacement for it, and deleting the narrative to make the index look
#      complete would lose the only account of WHY each of these happened.
#
# WHAT A COUNT FROM THIS FILE MEANS, AND WHAT IT DOES NOT. It is a count of what
# has been MIGRATED, not of what has HAPPENED. Because migration is partial, every
# count here is a LOWER BOUND — a class showing two occurrences may have had six.
# That asymmetry is safe in one direction only: this file can prove a defect
# recurs, and it can NEVER prove one did not.
#
#   grep -c '^defect_class: '                       how many kinds are registered
#   grep -c '^occurrence: '                         how many instances are migrated
#   scan-mutators.sh query DEFECT-0001-…            the instances of one kind
#   scan-mutators.sh recurrence                     every kind with more than one

# =============================================================================
# THE CLASSES. Thirteen. Twelve were demonstrated in the session that produced this
# file; the thirteenth was measured at the base of
# PACKET-0035-cross-surface-memory-kernel and is registered with its measurement.
# =============================================================================

defect_class: DEFECT-0001-stale-line-reference
title: A reference to a `path:line` that no longer names what it named
root_cause_class: reference_by_position
description: A citation identifies its subject by POSITION. Any edit above that line moves the subject and leaves the citation pointing at whatever slid into place. The citation still RESOLVES, so every check that asks "does this line exist" passes. This is the most-recurring defect in this repository's history.
detection_signature: a cited line whose content no longer matches the claim made about it; NOT detectable by resolvability, which is what scan-controls.sh actually checks
migration_status: seeded_partial

defect_class: DEFECT-0002-stale-remembered-count
title: A count quoted from memory rather than derived from the artefact
root_cause_class: remembered_not_derived
description: A number written into prose — "14 entries", "56 sites", "19 of 81" — that was true when written and is not re-derived when the artefact changes. The prose and the artefact drift apart silently because nothing compares them.
detection_signature: a literal count in prose with no test deriving it from the thing counted
migration_status: seeded_partial

defect_class: DEFECT-0003-duplicate-semantic-truth
title: The same fact stored in two places with no reconciliation between them
root_cause_class: unreconciled_redundancy
description: Two artefacts each assert the same fact. Redundancy is not itself the defect — this repository uses it deliberately, in the crosswalk and in the governance baseline — the defect is redundancy WITHOUT a check that compares the copies. Then one is edited, the other is not, and both continue to read as authoritative.
detection_signature: a value present in two files with no test asserting they are equal
migration_status: seeded_partial

defect_class: DEFECT-0004-guard-reconciles-labels-not-arguments
title: A guard that compares names while the thing that matters is the values
root_cause_class: checks_the_wrong_property
description: A check reconciles identifiers, labels or presence, and never reaches the arguments, thresholds or content those labels stand for. It goes green on a change that alters behaviour completely, because the labels did not move.
detection_signature: a guard whose assertions are all about existence or naming and none about a value
migration_status: seeded_partial

defect_class: DEFECT-0005-check-matches-wrong-output
title: A check asserting against output that is not the output under test
root_cause_class: checks_the_wrong_property
description: The assertion reads a different stream, a different file or a different invocation than the one whose behaviour is claimed. It passes and it proves nothing about the subject.
detection_signature: an assertion whose subject and whose source are not the same object
migration_status: seeded_partial

defect_class: DEFECT-0006-unchained-live-verification
title: A verification that exists but that nothing runs
root_cause_class: discoverable_only
description: A suite, a scanner or a check is written, works, and is wired into no command anybody actually runs. It protects only whoever already knows it exists — which is the author, on the day they wrote it.
detection_signature: an executable check that no aggregate command invokes
migration_status: seeded_partial

defect_class: DEFECT-0007-incomplete-enumeration
title: A list that presents itself as exhaustive and is not
root_cause_class: unbounded_claim
description: A set is enumerated — patterns, cases, files, mutators — and the enumeration is believed to be complete because it is written down. Nothing derives it from the tree, so members added later are silently outside it.
detection_signature: a hand-maintained list with no reconciliation against an independent scan
migration_status: seeded_partial

defect_class: DEFECT-0008-incomplete-application
title: A fix applied to some instances of a pattern and not to all of them
root_cause_class: unbounded_claim
description: A defect is understood and corrected where it was noticed. The same pattern elsewhere is left alone, because the sweep that found the first instance was a reading rather than a search.
detection_signature: a corrected instance of a pattern coexisting with uncorrected instances of the same pattern
migration_status: seeded_partial

defect_class: DEFECT-0009-silently-truncated-help-range
title: A range or slice whose bounds silently stop covering their subject
root_cause_class: reference_by_position
description: A `sed -n 'A,Bp'` help range, a head/tail bound or a slice that was correct when written and now truncates its subject because the subject grew. It emits output, exits 0, and the missing part is invisible to anybody who has not read the original.
detection_signature: a hard-coded line range over a file that is edited independently of it
migration_status: seeded_partial

defect_class: DEFECT-0010-same-model-review-correlation
title: A review whose independence is assumed rather than established
root_cause_class: correlated_judgement
description: Two gates that are supposed to be independent share the reasoning that produced the artefact, so they fail in correlated ways and agree on exactly the errors neither can see. Concurrency does not fix it; the passes are parallel but the blind spot is shared.
detection_signature: two gates that agree without either exercising the artefact
migration_status: seeded_partial

defect_class: DEFECT-0011-undeclared-active-packet
title: Work performed with no packet declared, passing a guard that only refuses two
root_cause_class: gate_permits_the_null_case
description: `bandwidth.active_packet_singleton` refuses TWO declared packets and permits ZERO. Work that simply omits its declaration passes clean, so the guard against doing too much at once is silent about doing it undeclared.
detection_signature: a cardinality gate with an upper bound and no lower bound
migration_status: seeded_partial

defect_class: DEFECT-0012-transient-evidence-destroyed-on-failure
title: Evidence deleted by the cleanup path that runs when the thing fails
root_cause_class: cleanup_outranks_diagnosis
description: A fixture, a work directory or a log lives under a `trap ... EXIT` that removes it. On success that is tidy. On FAILURE it destroys precisely the evidence needed to diagnose the failure, and the failure is the only case where anybody wanted it.
detection_signature: diagnostic state created inside a scope whose unconditional cleanup outlives the failure
migration_status: seeded_partial

defect_class: DEFECT-0013-pipefail-sigpipe-false-negative
title: A guard reports FAIL because of its own pipeline's exit semantics, not because the thing it checks is wrong
root_cause_class: harness_reports_its_own_plumbing
description: Under `set -o pipefail`, a producer killed by SIGPIPE when a short-circuiting consumer such as `grep -q` exits on the first match makes the pipeline return 141. The assertion is CORRECT, the data is CORRECT, and the check reports FAIL — nondeterministically, because whether the producer is still writing when the consumer exits is a scheduling race. It is strictly worse than a wrong assertion: it is a guard that is right about the world and wrong about itself, and it fails RARELY, so the natural response is to re-run and move on. CORRECTED CLAIM, and the earlier one — that this class "can never mask a real one" — WAS FALSE AS A CLASS CLAIM: ONE-DIRECTIONALITY IS A PROPERTY OF THE `&& ok || no` POLARITY, NOT OF THE CLASS: at that polarity the race can only manufacture a false FAIL, but INVERTED — `producer | grep -q . && no || ok` — the same 141 routes to `ok` and the identical race yields a FALSE PASS that masks a real failure. Measured counterexample, LATENT AND NOT LIVE: tests/build_os_maintenance_tests.sh:414 is written at that inverted polarity and returned non-zero 2000/2000 at 270890 B, 0/2000 with a draining consumer; it is unreachable today because it needs >64 KiB — roughly 1100+ leftover paths in a directory the test expects EMPTY — and it is invisible to the tests/build_os_tests.sh section 28 scanner, whose producer patterns do not enumerate `find`.
detection_signature: a pipeline of the shape `producer | grep -q` (or any early-exiting consumer) inside a script that sets pipefail, whose exit status is consumed as a verdict
migration_status: seeded_partial

defect_class: DEFECT-0014-retention-order-assumed-not-verified
title: A retention tool asserts a recency semantics it never verifies, so the artefact's own order silently decides whether the newest or the oldest content is destroyed
root_cause_class: unverified_ordering_assumption
description: build-os/maintenance/rotate-memory.mjs retains a PREFIX — routeSegments keeps blocks.slice(0, keepN) — while its report prints `keep N newest` and `selection : RECENCY ONLY`. It reads no date and has no way to establish a block's age: THE PREFIX IS THE AGE, BY ASSUMPTION. Where the artefact's own order contradicts that assumption the tool does the exact OPPOSITE of what it reports, at exit 0, and its byte-exact conservation check still passes because conservation holds in either direction. THE FAILURE IS INVISIBLE TO EVERY COUNT-DRIVEN GATE: block count, archived blocks, reclaimable bytes, post-rotation headroom and a full 1..N keep sweep are all IDENTICAL whether the order is right or wrong, so a re-block that inserts headings and leaves the order alone passes every check and still destroys the newest content on the first rotation. It stays latent wherever rotation has never run, which is also why it survives — the only signal is the loss itself, after the fact
detection_signature: a retention or eviction rule that selects by POSITION while its report, header or documentation claims selection by RECENCY, over an artefact whose ordering nothing enforces
migration_status: seeded_partial
