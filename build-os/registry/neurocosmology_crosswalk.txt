# Build OS — Neurocosmology crosswalk.
#
# The control registry answers "what kind of evidence is this control, and how
# much authority does it exercise?". This file answers the second question:
# WHAT UNIVERSAL FUNCTION DOES IT INSTANTIATE? Gravito is not computing
# Neurocosmology; it is operationalizing components of it, and this file records
# which components, at what strength, and — the load-bearing part — what each
# binding MISSES.
#
# THIS FILE CLASSIFIES. IT IMPLEMENTS NO MATHEMATICS, CREATES NO CONTROL, AND
# GRANTS NO AUTHORITY. There is no potential, no coherence measure, no goal
# ecology, no value-of-information term and no learned model here, and none may
# be added by editing this file. A binding is a claim ABOUT a control that
# already runs; every `class` and `runtime_authority` below is a COPY of that
# control's registry entry, kept deliberately redundant so the two files can be
# checked against each other. Where they disagree, the registry is right and
# this file is stale.
#
# TWO RECORD SHAPES, one field per line, a blank line between records:
#   `primitive:` records  — the 17 universal primitives (7 fields)
#   `control:` records    — one binding per registered control (6 fields)
#
# THE BINDING RULE. A control binds to the primitive whose FUNCTION it performs,
# not the primitive whose VOCABULARY its name shares. `adoption.boundary_manifest`
# bounds a claim, not a write scope, so it is epistemic_quality and not boundary.
# Exactly one primitive per control; where two fit, the tie goes to the primitive
# whose failure mode the control exists to prevent.
#
# binding_kind, strongest first — and only `instantiates` is coverage:
#   instantiates  the control performs the primitive's function.
#   proxies       it observes a stand-in for the function, and the stand-in's
#                 gap is named in the primitive's known_limitations.
#   nominal       it touches the concept without performing the function.
#                 A nominal binding is INFORMATION, NOT COVERAGE. Counting it as
#                 coverage is the inflation this crosswalk exists to refuse.
#   unbound       the control instantiates no primitive (rationale states why).
#
# `binding_kind` is a CONTROL-record field. `binding_quality`, on a PRIMITIVE
# record, is a DIFFERENT QUANTITY and is read wrongly if taken for a summary: it
# is the MAXIMUM binding_kind over that primitive's bound controls — the
# strongest kind any ONE of them holds — and section 7 of the suite enforces
# exactly that maximum, no more. So `binding_quality: instantiates` states that
# at least one binding instantiates and states NOTHING about the others:
# homeostasis carries it on the strength of 1 binding out of 25, and
# epistemic_quality on 14 out of 31. Grepping `^binding_quality: instantiates`
# answers "which primitives have any real contact at all"; it does NOT answer
# "which primitives are covered", and using it for the second question is the
# same inflation the nominal rule above exists to refuse. For coverage, use the
# honest-coverage recipe below, which COUNTS instantiating bindings per
# primitive rather than maximising over them.
#
#   grep -c '^primitive: '                  the 17 primitives
#   grep -c '^control: '                    the bindings — must equal the census size
#   grep '^binding_quality: unbound'        the primitives NOTHING binds to
#   grep -c '^binding_kind: nominal'        bindings that are not coverage
#
#   # honest coverage — instantiating bindings only, per primitive:
#   awk -F': ' '/^binds_to: /{p=$2} /^binding_kind: instantiates/{print p}' \
#     neurocosmology_crosswalk.txt | sort | uniq -c | sort -rn
#
# Pinned by tests/neurocosmology_crosswalk_tests.sh.

# =============================================================================
# THE 17 PRIMITIVES
# =============================================================================

primitive: reachability
universal_function: which futures are accessible from the current state
system_representation: affected-state graph; plan DAG; executable paths; available tools; authority-constrained actions
observable_proxies: the startup capability inventory — enabled plugins, native skills, and plugin-cache entries marked CANDIDATE
binding_quality: nominal
claimed_max_authority: advise
known_limitations: ONE BINDING, AND IT IS NOMINAL — this primitive has no coverage at any strength. It was carried as `proxies` until the reading was tightened: a proxy observes a stand-in that CO-VARIES with the function, and a list of tool names does not co-vary with which futures are reachable. It is an INVENTORY rather than a graph. Nothing in this repository constructs an affected-state graph, a plan DAG, or a set of executable paths, and nothing enumerates the futures an action opens or closes. `hooks.session_capability_report` lists capability NAMES and honestly marks the uncertain ones CANDIDATE — a list of nouns where the primitive requires a structure over verbs — and it exits 0 whatever it finds. Reachability as a computed object does not exist here.

primitive: meaning_metric
universal_function: which of the accessible futures matter
system_representation: product objective; acceptance criteria; task value; strategic priority
observable_proxies: none
binding_quality: unbound
claimed_max_authority: none
known_limitations: EMPTY, and the near-miss is named precisely so nobody fills the slot by relabelling. Acceptance criteria DO exist here in quantity — each of the seventeen test suites is a set of them — but an acceptance criterion is a BINARY PREDICATE OVER AN ARTEFACT THAT ALREADY EXISTS, and a meaning metric is a MEASURE OVER FUTURES. This registry holds 97 controls that can say "this is wrong" and none that can say "this is worth more than that". Binding the suites here would be exactly the inflation this crosswalk exists to refuse.

primitive: mass
universal_function: what pulls hardest on behaviour
system_representation: priority; severity; urgency; dependency-unlock value; attention weight
observable_proxies: the fixed ordering of the speed report's sections
binding_quality: nominal
claimed_max_authority: advise
known_limitations: NOMINAL ONLY, and it should be read as empty by anyone applying a strict standard. `metrics.report.disclosure_ordering` is the sole ordering of anything in the census, it takes `inputs: none`, and its order was chosen once by a human — so the system orders exactly one thing, a page layout, by constant. No control assigns severity, priority or urgency; the registry has no severity field; and `runtime_authority: rank` — the authority tier that exists precisely to order work or select between options — is held by ZERO of 97 controls, as is `observe`. Nothing here computes what pulls hardest from state.

primitive: valence
universal_function: which directions are attractive and which are harmful
system_representation: benefit; harm; expected loss; user impact
observable_proxies: none
binding_quality: unbound
claimed_max_authority: none
known_limitations: EMPTY. The nearest thing is `authority_mismatch: declared`, which labels 14 entries as carrying more authority than their class licenses — a DIRECTION of risk, but hand-assigned, binary, and attached to a control rather than to any future. Nothing computes benefit, harm, expected loss or user impact. The metrics store carries a `defects_gated` column that counts caught harm after the fact; it has no notion whatever of the magnitude of what was caught, so a typo and a data-loss bug increment it identically.

primitive: agency
universal_function: the ability to produce movement
system_representation: tools; permissions; authority leases; effective execution capability
observable_proxies: PATH resolution of required binaries; the handoff lock's acquired or BUSY state and its pid liveness; the capability-profile subcommand
binding_quality: instantiates
claimed_max_authority: execute
known_limitations: ELEVEN BINDINGS, EIGHT INSTANTIATING — AND THE SHAPE OF THE PRIMITIVE CHANGED WHEN THE MUTATOR CENSUS LANDED. It carried five bindings until then, four of them binary preconditions; this record described that set and is rewritten because six `execute` bindings were added, not because a number moved. THE SIX ARE THE FIRST OCCUPANTS OF `execute` ANYWHERE IN THIS FILE: `maint.rotation_live_file_replacement`, `swarm.merge_commit_execution`, `metrics.record.store_append`, `metrics.decision.store_append`, `identity.stamp_write`, `tools.handoff_lock_lifecycle`. They are the reason this primitive is no longer described by preconditions: agency is the ability to PRODUCE MOVEMENT, and until these were registered the census bound only checks that ran BEFORE movement and never the movement itself. That is a real gain and it is smaller than it looks — each is one write site, classified; none measures capacity, and none is a quantity. THE PRECONDITIONS REMAIN AND REMAIN BINARY — is the tool on PATH, is the lock free, is the subcommand valid. `tools.handoff_lock` is a genuine authority lease and the closest thing here to agency as a quantity, but it is one bit, and `tools.capability_profile_usage` is NOMINAL: it validates a subcommand's arguments, guarding the switch that sets effective capability without ever observing capability. Nothing represents degrees of capability and nothing models what an agent can actually accomplish. `envelope.grant_composition` is the only binding that is neither a precondition nor a write: it represents an authority lease as a STRUCTURE — issuer, actor, scope, granted authority, evidence basis, deployment mode, start, expiry, revocation, rollback — and its deployment mode is the only representation anywhere here of whether an output is consumed, confirmed by a person, acted on within bounds, or acted on freely. It is still a PROXY and the reason is the one below, which it does not escape: the lease it validates is DECLARED, nothing enforces it, and NO LIVE GRANT EXISTS — the store ships empty, so this binding is real machinery over an empty set. Decisively, and unchanged by it: the permission system that really constrains agent action is EXTERNAL to this repository, so the census is structurally blind to the largest determinant of agency in the running system.

primitive: energy
universal_function: the capacity to act and to integrate
system_representation: compute budget; context budget; WIP; tool availability; latency; agent capacity
observable_proxies: a 900-second supervise budget; 900, 30 and 1800-second handoff budgets; a 30000-character startup skill budget
binding_quality: proxies
claimed_max_authority: gate
known_limitations: THREE BINDINGS, NONE INSTANTIATING, and every constant inside them is unvalidated or assumed. `tools.skill_budget_audit` is the only real capacity accounting and it still only proxies: 30000 is an assumed platform constant its own entry says must be verified, SKILL.md byte size only approximates token cost, and it EXITS 0 WHEN OVER BUDGET, so the one control that measures capacity cannot act on its own measurement — a measurement that cannot bind the measurer is a stand-in for capacity management, not an instance of it. The two timeout controls treat wall-clock as a stand-in for capacity, which is the crudest proxy available: a run that is slow because it is thorough and a run that is slow because it is stuck produce the same number.

primitive: homeostasis
universal_function: staying stable while operating
system_representation: runtime health; test state; repo cleanliness; dependency integrity; recovery
observable_proxies: seventeen suite RESULT lines; merge preconditions over git status; post-merge verification; hook idempotence; static assertions over the maintenance layer's own source
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: THE LARGEST COUNT IN THIS CROSSWALK AND THE ONE MOST AT RISK OF BEING MISREAD. Seventeen of its twenty-two bindings are test suites, and a suite's empirical status is `red_driven` — the registry README's concession applies here at full force: a check written against a fixture written by the same author in the same hour mostly proves the two agree. A green suite is evidence that PLANTED defects are caught. It is not a measurement of system health. There is no runtime health signal in this system at all, and nothing observes the system WHILE it operates: every binding here is a pre-condition or a post-condition around a run, never a state variable during one. `suite.build_os_maintenance` is the only binding that exercises recovery, and it does so against a cold install in a scratch repo rather than against a damaged live one.

primitive: integration_bandwidth
universal_function: how much change can be safely absorbed
system_representation: WIP limits; review capacity; merge bandwidth; evidence capacity
observable_proxies: the number of packet ids declared in build-os/packets/active_packet.md; the commit count between a packet's declared base and HEAD
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: NO LONGER EMPTY, AND THE TWO BINDINGS COVER TWO OF FOUR CONVENTIONS. The four conventions are: one active packet, at most two commits per packet, a bounded fix round, a median depth of two serial stages. THREE OF THE FOUR ARE STATED IN CLAUDE.md — the commit ceiling in the working contract, the bounded fix round and the median depth in the depth budget. THE FOURTH IS NOT. "One packet at a time" appears NOWHERE in CLAUDE.md; it lives only in the prose header of `build-os/packets/active_packet.md`, which is the very file `bandwidth.active_packet_singleton` reads — a ceiling resting on a docstring inside the artefact being checked, which is why that control is Class C and declares an authority mismatch rather than claiming its number is a definition. AN EARLIER VERSION OF THIS RECORD LISTED "bounded open write sets" AS THE THIRD CONVENTION; THAT WAS WRONG AND IS CORRECTED HERE. CLAUDE.md's fan-out gate requires a DISJOINT file-ownership manifest, not a bounded NUMBER of concurrent write sets, and `bandwidth-check.sh`'s own header says so; no ceiling on their number is declared anywhere in this system. `bandwidth.active_packet_singleton` refuses a second declared packet and is the first control in the census that limits what may be absorbed rather than judging what already exists. `bandwidth.packet_commit_ceiling` only PROXIES: it measures and then exits 0, so it cannot bind the thing it measures, and its base is self-declared by the agent it constrains. THE TWO DIMENSIONS THE TOOL DOES NOT IMPLEMENT ARE DECLINED OUT LOUD RATHER THAN QUIETLY MISSING, AND THEY ARE DECLINED FOR DIFFERENT REASONS — a distinction worth protecting, because the weaker reason is the one it would be convenient to upgrade. Depth is declined because it is genuinely UNOBSERVABLE: rounds and serial agent stages are TRANSCRIPT-ONLY, nothing in git attests to how many agent passes ran in series, one commit can be one stage or five, and a control claiming to enforce a limit it cannot observe would be worse than an absent one. Open write sets are declined for a DIFFERENT AND WEAKER REASON: they ARE observable — a fan-out manifest names each agent's writable set — and the only obstacle is that NO ceiling on their number is declared, so enforcing one would mean inventing a constant, the anti-pattern that a composite load score would also be. Calling both dimensions unobservable would be the safer-sounding claim and the false one. Nothing here models review capacity, merge bandwidth or evidence capacity, and nothing observes capacity WHILE work is in flight: both bindings read state between actions, never during one.

primitive: boundary
universal_function: which movements are permitted
system_representation: action classes; write scopes; policy rules; authority ceilings
observable_proxies: hash snapshots of the real memory files taken in-process and again in-shell; presence of the tripwire module; the GRAVITO:MANAGED banner set
binding_quality: proxies
claimed_max_authority: gate
known_limitations: EVERY BOUNDARY HERE IS DETECTIVE, NOT PREVENTIVE, SO NOT ONE OF THE FOUR INSTANTIATES. The tripwire and the shell fingerprint both work by hashing before and after and naming what changed — so the prohibited write HAPPENS, and is then reported. That is worth having, and `maint.real_memory_tripwire` is field_observed against a real suite that destroyed live memory at exit 0, but it is not what the primitive means: a boundary that constrained reachable futures would refuse the write. The counter-argument is real and is recorded rather than discarded: both are `gate`, so the offending change cannot LAND even though the write does — the boundary is enforced at COMMIT granularity, not at WRITE granularity. That is why they proxy the primitive rather than failing to touch it, and it is also the precise size of the gap: any damage done between the write and the commit is out of scope for every boundary control in the census. Three of the four bindings police one narrow scope, the memory files. The authority ceilings that DO exist — the class-to-authority licence table — are enforced by `registry.reconciliation`, which binds to epistemic_quality because it checks that a mismatch is DECLARED, never that it is permitted.

primitive: ethical_admissibility
universal_function: which futures must not be entered at all
system_representation: legal; security; privacy; safety; policy invariants
observable_proxies: file digests and LICENSE on an installed copy; a fixed egress pattern set matched against the twelve files of the entitlement packet
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: OFF NOMINAL-ONLY FOR THE FIRST TIME, AND THE MOVE IS SMALLER THAN IT LOOKS. `entitlement.egress_scan` genuinely instantiates: it refuses an artefact that would enter an inadmissible future — a build of this product that transmits to a remote host — and, unlike every binding under `boundary`, the prohibited ACT never occurs, so it is preventive rather than detective. Its scope is twelve named files from one packet, not the tree, so egress introduced anywhere else is invisible to it. The other binding remains NOMINAL: a provenance check, whose own rationale concedes the distance, because a digest match proves the files are unmodified and never that any particular USE of them is permitted. THE STRONGEST RULE THIS SYSTEM STATES ABOUT ITSELF STILL HAS ZERO REGISTERED CONTROLS, and this is the sentence to read twice: no external mutation without explicit go — never push, merge, deploy, publish or touch secrets — is enforced by the operator's PERMISSION SYSTEM, a process boundary outside this repository, and nothing in the census gates a push, a deploy, a publish or a credential read. That is not an oversight to be closed by a control here: anything able to bypass the permission system bypasses a repo-side check trivially, so a repo-side gate would convert a real external boundary into a checkbox that looks enforced and is not. This primitive's strongest enforcement lives OUTSIDE the census and the census remains blind to it. What did change is README section 4's known hole number 1 — a control added inside an already-registered file — closed for the one instance that motivated it: the egress scan was previously visible only as part of `suite.entitlement`'s test state.

primitive: epistemic_quality
universal_function: how good the system's contact with reality is
system_representation: evidence coverage; receipts; calibration; claim-state reconciliation
observable_proxies: git numstat recomputation of claimed row values; vacuity refusals across seven surfaces; occupancy and length floors on evidence rows; the tree-derived discovery rule
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: THIRTY-ONE BINDINGS, AND THE COUNT OVERSTATES THE CONTACT. 75 of the 97 controls in this registry are `red_driven` and only 3 are `field_observed`, so most of what binds here has been shown to fire on a defect its own author planted, and nothing more. The bindings divide sharply. A small group compares a claim against something the claimant did not write — `metrics.record.verify_git` against git numstat, `adoption.lane_size_check` against measured churn, `registry.discovery_rule` against the tree — and those genuinely instantiate the primitive. The larger group checks SHAPE, OCCUPANCY, LENGTH or VACUITY: `adoption.boundary_manifest` validates that a manifest is well-formed and not that the boundary it declares is true, which is why it sits with its siblings `adoption.schema_invariant` and `adoption.store_validate` rather than above them; `metrics.record.note_minimum` passes twelve repeated characters, `adoption.junk_row_thresholds` scores a row of plausible fabrications as full, and seven separate "the scan found nothing" refusals prove only that a check was not blind — a necessary condition for evidence and never a sufficient one. `maint.tripwire_coverage_scan` is registered `refuted`: measured, and found not to discriminate. Nothing here is `calibrated` except two threshold controls fitted to n=4 packets of this repository's own history. Reading "31 of 97" as dense epistemic coverage would be the overclaim the registry exists to prevent.

primitive: latent_state
universal_function: hidden state beneath the explicit claims
system_representation: contradiction detection; unstated dependencies; claim-state gap; drift
observable_proxies: row counts at four render stages; receipt stems against store rows; module specifiers recovered from source; suites on disk against suites chained; RESULT lines against exit codes
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: Five bindings, and every one is a PAIRWISE EQUALITY between two places that were already supposed to agree. That is contradiction detection at its narrowest: each check is told in advance which two things to compare, so it can only find a divergence somebody already anticipated. Nothing here searches for unstated dependencies in general — `maint.source_scan_mask` recovers declared module specifiers with a heuristic lexer and is itself registered `refuted`. Nothing carries state across runs, so DRIFT in the temporal sense is not observed at all; all five fire within a single invocation. The claim-state gap this system actually suffers from — an artefact whose prose has quietly stopped describing the tree — is caught only at the specific pairings someone thought to write down.

primitive: durability
universal_function: what persists through time
system_representation: D1, D7, D30 and D90 retention; rollback; rework; escaped regressions
observable_proxies: byte conservation across a memory rotation
binding_quality: proxies
claimed_max_authority: gate
known_limitations: ONE BINDING, AND IT INSTANTIATES NOTHING: it measures durability across a single TRANSFORMATION rather than across TIME, and it touches NONE of the five representations this record declares — not D1, D7, D30 or D90 retention, not rollback, not rework, not escaped regressions. `maint.rotation_conservation` proves no byte is lost when memory is rotated; it says nothing about whether anything survives a week. The temporal quantities the primitive names are not merely unmeasured — for one of them the INSTRUMENT EXISTS AND IS EMPTY: `packet_metrics.tsv` carries a `defects_escaped` column and it reads `-` in all 8 of 8 rows, so the system has built a place to record escaped regressions and has never recorded one. Nothing computes D1, D7, D30 or D90. Nothing measures rework. And `rollback_behavior` is a prose field on every one of the 97 registry entries that no control ever executes, tests or verifies.

primitive: gated_plasticity
universal_function: changing the rules safely
system_representation: amendment lane; staged policy changes; rollback; quorum; external authorization
observable_proxies: a justified override token that must cite the measured value; a computed-but-unauthorised threshold drift report; two cross-file pinnings of a threshold and a budget
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: THE BEST-SERVED PRIMITIVE RELATIVE TO ITS SIZE, and the only one where the system's own design reasoning matches the primitive's intent explicitly: `adoption.threshold_drift_advisory` computes what the rule WOULD become and refuses to be promoted, on the stated grounds that a threshold following the data is a control surface for whoever writes the data. What is missing is everything social. There is no quorum, no external authorization, no staging and no rollback of a rule change. An amendment here is a commit by whoever is at the keyboard; these guards ensure a rule cannot change in ONE PLACE ONLY, not that the change was ever authorised. `adoption.lane_override` is a real amendment lane, but it is policed for FORM — a justification of sufficient length that names the measured file count — and never for merit.

primitive: collective_coherence
universal_function: alignment across multiple agents
system_representation: shared canonical state; conflict graph; plan agreement; cross-agent reconciliation
observable_proxies: pairwise glob overlap; per-path ownership cardinality; hot-file reservations and releases; claimed versus actual changed paths
binding_quality: instantiates
claimed_max_authority: gate
known_limitations: Five bindings, and structurally they are the most faithful group in this crosswalk — `swarm.disjointness` really does compute a conflict graph, before the conflict. The limitation is that all five reason over FILE PATHS and nothing else. Two agents editing disjoint files can still hold contradictory beliefs, implement incompatible designs, or duplicate each other's work entirely, and every one of these controls passes them without comment. Coherence is enforced as non-collision in a namespace, which is the cheapest available proxy for agreement. All five are also `red_driven` against fixture manifests; not one has been exercised by a real fan-out that actually went wrong.

primitive: goal_ecology
universal_function: balancing several legitimate objectives at once
system_representation: speed; correctness; safety; cost; maintainability; learning; human attention
observable_proxies: none
binding_quality: unbound
claimed_max_authority: none
known_limitations: EMPTY, and the trade-offs are real but FROZEN. The lane table trades speed against scrutiny, the depth budget trades wall-clock against serial gates, and the skill budget trades capability against context — three genuine multi-objective trades, each resolved once by a human and written down as a constant. A constant is the RESULT of a balance, not the act of balancing. No control weighs two objectives against each other at runtime, and it could not: because nothing computes valence and nothing computes mass, there is no quantity for such a control to weigh.

primitive: wisdom
universal_function: choosing the right scale and horizon to act at
system_representation: routing across line, file, feature, system and governance scales; regret-aware scale selection
observable_proxies: a keyword classification of the user's prompt into a lane
binding_quality: nominal
claimed_max_authority: advise
known_limitations: ONE BINDING, NOMINAL, and it is the only control in the census that SELECTS rather than judges — which is exactly why the prediction that this half is empty is very nearly right rather than exactly right. `hooks.prompt_router` reads prompt text and names a lane, but it classifies by keyword, is `unvalidated`, exits 0 on every path including its own dedup miss, is enforced by nothing, and — decisively — receives NO OUTCOME FEEDBACK, so it cannot be regret-aware in any sense the primitive would recognise. The system's other scale machinery, `adoption.lane_size_check`, binds to epistemic_quality because it AUDITS a scale claim after the commits already exist rather than choosing a scale. Selecting a scale and being judged on that selection are different acts, and only the first is present here, in its weakest possible form.

control: metrics.record.schema_invariant
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: proxies
rationale: Validates the shape of an evidence row before it is written, so the store cannot accumulate rows that mean nothing. Shape is a proxy for soundness: a perfectly well-formed row can still be false.

control: metrics.record.note_minimum
binds_to: epistemic_quality
class: C
runtime_authority: gate
binding_kind: nominal
rationale: A 12-character floor on the attributing note. It enforces the PRESENCE of prose, not attribution — twelve repeated characters pass. The invariant underneath it (a row must carry a note) would instantiate; the length does not.

control: metrics.record.one_row_per_packet
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: proxies
rationale: Key uniqueness stops a double-counted packet silently inflating every downstream total. It protects the arithmetic over the evidence, not the evidence's correspondence to what happened.

control: metrics.record.store_validate
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: proxies
rationale: Re-runs the write-path validator over the whole store and refuses a zero-row store as unmeasured rather than valid. Whole-file shape checking; still shape.

control: metrics.record.verify_git
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: instantiates
rationale: The strongest epistemic control in the census: each row's claimed files, insertions and deletions are recomputed from `git show --numstat`, an artefact the claimant did not author. This is contact with reality rather than agreement with a fixture.

control: metrics.record.verify_git_vacuity
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: instantiates
rationale: Refuses when zero rows were actually compared. A verifier that verified nothing and reported success is precisely the failure this primitive names.

control: metrics.report.empty_store_refusal
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: instantiates
rationale: Refuses to render a report over no data. Reporting on an empty store is the minimal overclaim, and it is refused outright.

control: metrics.report.render_reconciliation
binds_to: latent_state
class: A
runtime_authority: gate
binding_kind: instantiates
rationale: Counts rows at four pipeline stages — counted, read, rendered, skipped-as-ragged — and fails on disagreement. A row dropped between stages is state the rendered output does not mention and cannot reveal.

control: metrics.report.unmeasured_total_is_dash
binds_to: epistemic_quality
class: A
runtime_authority: advise
binding_kind: instantiates
rationale: Prints `-` where no row contributed rather than 0. Refusing to present absence as a measurement is epistemic quality in the purest form available here.

control: metrics.report.disclosure_ordering
binds_to: mass
class: A
runtime_authority: advise
binding_kind: nominal
rationale: The ONLY ordering of any kind in the census, and it takes `inputs: none` — a fixed section order a human chose once, placing the caveat above the numbers. It allocates a reader's attention without computing what deserves it. Ordering by constant is not mass.

control: adoption.boundary_manifest
binds_to: epistemic_quality
class: A
runtime_authority: gate
binding_kind: proxies
rationale: Dates and reasons the scope within which an adoption claim is valid, so grandfathering cannot quietly shrink the evidence base. Bound by function rather than by name: it bounds a CLAIM, not a write scope. PROXIES only — it validates that the manifest is WELL-FORMED, never that the boundary it declares is true, which is the shape-and-occupancy check the primitive's own known_limitations criticises and puts it level with `adoption.schema_invariant` and `adoption.store_validate` rather than above them.

control: adoption.receipt_row_reconciliation
binds_to: latent_state
class: A
runtime_authority: gate
binding_kind: instantiates
rationale: Two internal records of the same packets — receipt stems and store rows — must agree, and a MISSING is the gap between what governance recorded and what measurement recorded. Field-observed: the only binding in this crosswalk that has fired on a defect nobody planted.

control: adoption.junk_row_thresholds
binds_to: epistemic_quality
class: C
runtime_authority: gate
binding_kind: proxies
