# Build OS — mutator census.
#
# One record per action in this repository that CHANGES DURABLE STATE. One field
# per line; a blank line separates records; `#` at column 0 is a comment. The
# format is control_registry.txt's on purpose — the same parser reads it, the
# same grep habits work on it.
#
# WHY THIS FILE HAD TO EXIST SEPARATELY, AND IT IS NOT A STYLE CHOICE.
# control_registry.txt's field list is CLOSED: scan-controls.sh refuses the whole
# file on an unknown field name, and its "every field present" check would fail
# all 81 pre-existing entries the moment a new field was added to the enum. So
# the mutator's extra fields cannot live there. This store is keyed by
# `control_id` instead, and the control registry is not widened by one byte.
#
# WHAT THE CENSUS FOUND, AND IT IS THE POINT OF THE FILE. Every control whose
# owning_module is one of these mutating modules classified THE CHECK AND NOT THE
# WRITE. `swarm.disjointness` classifies a refusal. `tools.handoff_lock`
# classifies a fail-closed acquisition. `metrics.record.schema_invariant`
# classifies a validation that runs BEFORE the append. `maint.rotation_conservation`
# classifies a conservation property of a plan. The write actions themselves —
# the rename onto the live memory file, the commit, the append, the stamp, the
# lock — were registered at NO AUTHORITY AT ALL. That is what this census fixes.
#
# THE RECORD KEY IS THE STABLE ID. `mutator: MUT-0001-…` — the key IS the
# `stable_mutator_id`, and there is deliberately no second field repeating it.
# Storing the same truth twice is itself one of the registered defect classes
# (DEFECT-0003-duplicate-semantic-truth), and a census that commits the defect it
# records is not worth reading.
#
# IDS ARE NOT POSITIONS. `MUT-0001-…` survives every edit to every file. The
# `evidence_refs` are `path:line` and are NAVIGATION HINTS ONLY: they are checked
# to resolve and to support the declared mutation_type, and nothing anywhere is
# identified by them. Seven consecutive packets shipped a stale `:NNN`; an
# identifier that moves when somebody adds a comment is not an identifier.
#
# `runtime_authority` IS A COPY of the live control_registry.txt entry, kept
# deliberately redundant so the two files can be checked against each other — the
# same device neurocosmology_crosswalk.txt uses. WHERE THEY DISAGREE THE REGISTRY
# IS RIGHT AND THIS FILE IS STALE, and tests/mutator_registry_tests.sh section 2
# fails on the disagreement rather than picking a winner.
#
# `required_authority` IS NOT A COPY, AND IT IS THE LOAD-BEARING FIELD. It is what
# the ACTUAL BEHAVIOUR requires under the corrected ladder, derived from README §2's
# own mechanical test for the top rung — "performs a durable write" — and NOT from
# what the control is currently granted. Where the two differ, the gap is a
# FINDING in findings.txt, addressed to the operator, and NOTHING HERE APPLIES IT.
# Two records carry that gap today (MUT-0007, MUT-0008) and both are left where
# they are: re-authorising an existing control is a governance act, and this file
# performs none.
#
# WHY `execute` AND NOT `gate`, FOR THE SIX THAT REACH IT. `gate` is "may allow or
# prohibit"; `execute` is "may directly cause mutation". These six do not decide
# whether a change is permitted — they ARE the change. NO CLASS LICENSES
# `execute`, so every one of them declares `authority_mismatch: declared` in the
# control registry and takes a row in MISMATCHES.md. THAT IS A RECORD OF AN
# OVER-AUTHORISATION, NOT A GRANT: the licence table is untouched and 0 of its 25
# cells reach the rung. The rung was populated because six actions met its stated
# test, and a candidate that only PROPOSES a mutation would not be here.
#
# THE SCAN'S THREE EXCLUSIONS, stated here because an exclusion nobody can audit
# is how a census shrinks quietly. tests/mutator_registry_tests.sh section 1 scans
# the tree for durable-write syntax and requires every hit to be censused. THREE
# MODULES MATCH THE PATTERN AND ARE EXCLUDED, FOR THE SAME REASON AND NOT FOR
# THREE: `build-os/tools/authority-envelope.sh`, `build-os/tools/claim-evidence.sh`
# and `build-os/tools/mismatch-disposition.sh` each append only to paths obtained
# from `mktemp`, which their own `trap` removes on exit, so none of them changes
# any durable state.
# `build-os/registry/scan-controls.sh` has the same shape and is not scanned at
# all. The pattern is syntactic and cannot tell those apart from a real store;
# the exclusion is the honest handling, and the test fails if this reason is ever
# deleted. THE EXCLUSION IS NOT A LICENCE TO ADD MORE: a module that writes
# anywhere a `trap` does not remove belongs in the census, and the reason each
# exclusion states is the thing a reviewer checks against the module's source.
#
# WHAT THIS CENSUS DOES NOT CLAIM. `write_scope` is the author's word. Section 3
# of the suite derives from the tree that a declared mutation_type is SUPPORTED by
# a line the record cites; it does NOT prove the write scope is COMPLETE. A
# mutator that writes somewhere nobody wrote down is not caught here, and the
# independent scan is the only thing pushing back on that.
#
#   grep -c '^mutator: '                          how many actions are censused
#   grep -B2 '^required_authority: execute'       what directly changes state
#   awk -F': ' '/^mutator: /{m=$2} /^required_authority: /{r=$2} \
#     /^runtime_authority: /{if($2!=r) print m}'  where authority lags behaviour
