# Build OS — mutator census.
#
# One record per action in this repository that CHANGES DURABLE STATE. One field
# per line; a blank line separates records; `#` at column 0 is a comment. The
# format is control_registry.txt's on purpose — the same parser reads it, the
# same grep habits work on it.
#
# WHY THIS FILE HAD TO EXIST SEPARATELY, AND IT IS NOT A STYLE CHOICE.
# control_registry.txt's field list is CLOSED: scan-controls.sh refuses the whole
# file on an unknown field name, and its "every field present" check would fail
# all 81 pre-existing entries the moment a new field was added to the enum. So
# the mutator's extra fields cannot live there. This store is keyed by
# `control_id` instead, and the control registry is not widened by one byte.
#
# WHAT THE CENSUS FOUND, AND IT IS THE POINT OF THE FILE. Every control whose
# owning_module is one of these mutating modules classified THE CHECK AND NOT THE
# WRITE. `swarm.disjointness` classifies a refusal. `tools.handoff_lock`
# classifies a fail-closed acquisition. `metrics.record.schema_invariant`
# classifies a validation that runs BEFORE the append. `maint.rotation_conservation`
# classifies a conservation property of a plan. The write actions themselves —
# the rename onto the live memory file, the commit, the append, the stamp, the
# lock — were registered at NO AUTHORITY AT ALL. That is what this census fixes.
#
# THE RECORD KEY IS THE STABLE ID. `mutator: MUT-0001-…` — the key IS the
# `stable_mutator_id`, and there is deliberately no second field repeating it.
# Storing the same truth twice is itself one of the registered defect classes
# (DEFECT-0003-duplicate-semantic-truth), and a census that commits the defect it
# records is not worth reading.
#
# IDS ARE NOT POSITIONS. `MUT-0001-…` survives every edit to every file. The
# `evidence_refs` are `path:line` and are NAVIGATION HINTS ONLY: they are checked
# to resolve and to support the declared mutation_type, and nothing anywhere is
# identified by them. Seven consecutive packets shipped a stale `:NNN`; an
# identifier that moves when somebody adds a comment is not an identifier.
#
# `runtime_authority` IS A COPY of the live control_registry.txt entry, kept
# deliberately redundant so the two files can be checked against each other — the
# same device neurocosmology_crosswalk.txt uses. WHERE THEY DISAGREE THE REGISTRY
# IS RIGHT AND THIS FILE IS STALE, and tests/mutator_registry_tests.sh section 2
# fails on the disagreement rather than picking a winner.
#
# `required_authority` IS NOT A COPY, AND IT IS THE LOAD-BEARING FIELD. It is what
# the ACTUAL BEHAVIOUR requires under the corrected ladder, derived from README §2's
# own mechanical test for the top rung — "performs a durable write" — and NOT from
# what the control is currently granted. Where the two differ, the gap is a
# FINDING in findings.txt, addressed to the operator, and NOTHING HERE APPLIES IT.
# Two records carry that gap today (MUT-0007, MUT-0008) and both are left where
# they are: re-authorising an existing control is a governance act, and this file
# performs none.
#
# WHY `execute` AND NOT `gate`, FOR THE SIX THAT REACH IT. `gate` is "may allow or
# prohibit"; `execute` is "may directly cause mutation". These six do not decide
# whether a change is permitted — they ARE the change. NO CLASS LICENSES
# `execute`, so every one of them declares `authority_mismatch: declared` in the
# control registry and takes a row in MISMATCHES.md. THAT IS A RECORD OF AN
# OVER-AUTHORISATION, NOT A GRANT: the licence table is untouched and 0 of its 25
# cells reach the rung. The rung was populated because six actions met its stated
# test, and a candidate that only PROPOSES a mutation would not be here.
#
# THE SCAN'S TWO EXCLUSIONS, stated here because an exclusion nobody can audit is
# how a census shrinks quietly. tests/mutator_registry_tests.sh section 1 scans
# the tree for durable-write syntax and requires every hit to be censused. TWO
# MODULES MATCH THE PATTERN AND ARE EXCLUDED, FOR THE SAME REASON AND NOT FOR TWO:
# `build-os/tools/authority-envelope.sh` and `build-os/tools/claim-evidence.sh`
# each append only to paths obtained from `mktemp`, which their own `trap`
# removes on exit, so neither changes any durable state.
# `build-os/registry/scan-controls.sh` has the same shape and is not scanned at
# all. The pattern is syntactic and cannot tell those apart from a real store;
# the exclusion is the honest handling, and the test fails if this reason is ever
# deleted. THE EXCLUSION IS NOT A LICENCE TO ADD MORE: a module that writes
# anywhere a `trap` does not remove belongs in the census, and the reason each
# exclusion states is the thing a reviewer checks against the module's source.
#
# WHAT THIS CENSUS DOES NOT CLAIM. `write_scope` is the author's word. Section 3
# of the suite derives from the tree that a declared mutation_type is SUPPORTED by
# a line the record cites; it does NOT prove the write scope is COMPLETE. A
# mutator that writes somewhere nobody wrote down is not caught here, and the
# independent scan is the only thing pushing back on that.
#
#   grep -c '^mutator: '                          how many actions are censused
#   grep -B2 '^required_authority: execute'       what directly changes state
#   awk -F': ' '/^mutator: /{m=$2} /^required_authority: /{r=$2} \
#     /^runtime_authority: /{if($2!=r) print m}'  where authority lags behaviour

# =============================================================================
# THE FIVE NAMED BY THE PACKET BRIEF — confirmed by survey, not trusted from the
# list. Each is registered as a NEW control at `execute`; none of the five write
# actions was registered at any authority before this census existed.
# =============================================================================

mutator: MUT-0001-rotation-live-file-replacement
control_id: maint.rotation_live_file_replacement
actor_or_tool: build-os/maintenance/rotate-memory.mjs
trigger: an operator or a maintenance job running rotate-memory.sh --apply; the default path is a dry run and writes nothing
read_scope: the three rotating memory files, their `## ` block structure, and the existing archive directory
write_scope: build-os/memory/current_state.md, build-os/memory/residue.md, build-os/packets/active_packet.md, and new files under build-os/memory/archive/
mutation_type: replace
rollback_behavior: partial and asymmetric — the rotated-out blocks are preserved in the archive and can be pasted back by hand, but the live file is REPLACED and its prior bytes exist only in git. There is no --undo.
required_authority: execute
runtime_authority: execute
deployment_mode: human_confirmed
implementation_status: load_bearing
empirical_status: red_driven
evidence_refs: build-os/maintenance/rotate-memory.mjs:982; build-os/maintenance/rotate-memory.mjs:1006
receipt_behavior: none of its own — it prints a plan and an applied summary to stdout, and the only durable proof it ran is the archive file it created plus git. THE MOST CONSEQUENTIAL WRITE IN THIS SYSTEM EMITS NO RECEIPT.
notes: The rename at :1006 is the whole reason this census exists. A staging file is written at :982, read back, verified byte-for-byte and checked against an append-only precondition, and only then renamed ONTO the live memory file — so the write is as careful as it could be while still being a replacement. `maint.rotation_conservation` already classified the PLAN's conservation property; nothing classified the rename. Note the asymmetry that makes this the sharpest entry here: the tool that rewrites Build OS memory is the tool whose own execution leaves the least evidence.

mutator: MUT-0002-swarm-merge-commit
control_id: swarm.merge_commit_execution
actor_or_tool: build-os/tools/swarm-merge.sh
trigger: `swarm-merge.sh merge --manifest FILE --commit MSG`. WITHOUT `--commit` the tool stages and verifies and does NOT commit, which is the default.
read_scope: the fan-out manifest, the working tree, the git index, and the verification command's exit status
write_scope: the git index and one new commit on the current branch of the target repository
mutation_type: commit
rollback_behavior: reversible — `git reset --hard HEAD^` restores the prior tip, and the tool has its own `rollback` path that runs if the commit itself fails. The commit is LOCAL; this tool never pushes, by construction.
required_authority: execute
runtime_authority: execute
deployment_mode: human_confirmed
implementation_status: load_bearing
empirical_status: red_driven
evidence_refs: build-os/tools/swarm-merge.sh:101; build-os/tools/swarm-merge.sh:586
receipt_behavior: prints the short SHA and the message on stdout; the commit itself is the durable receipt, and it is the only mutator here whose receipt is a first-class git object
notes: CITED AT :101 AND :586 RATHER THAN AT THE `git commit` LINE, AND THE REASON IS RECORDED SO IT DOES NOT LOOK LIKE EVASION. `build-os/tools/swarm-merge.sh:587` — the invocation itself — is ALREADY CLAIMED by `swarm.post_merge_verification`, and control_registry_tests.sh section 22 forbids one line carrying two classifications. The two lines cited instead are the flag that enables the commit (:101) and the branch that decides it happens (:586), which are the lines that make the mutation reachable. Repointing the other entry to free :587 would have been the technique scan-controls.sh's own header names as hole 5 — shedding authority by narrowing evidence_refs — so it was not done.

mutator: MUT-0005-handoff-lock-lifecycle
control_id: tools.handoff_lock_lifecycle
actor_or_tool: build-os/tools/specialist-handoff.sh

mutation_type: lock
rollback_behavior: self-releasing — `safe_release_lock` removes the pid file and rmdirs the lock, guarded by a path-safety check that refuses "/", ".", ".." and $HOME. A crashed holder leaves a stale lock, which is reclaimed by the staleness rule rather than by a human.
required_authority: execute
runtime_authority: execute
deployment_mode: human_confirmed
implementation_status: load_bearing
empirical_status: unvalidated
evidence_refs: build-os/tools/specialist-handoff.sh:122; build-os/tools/specialist-handoff.sh:166
receipt_behavior: an append-only line in $HANDOFF_LOG carrying timestamp, route, result and exit — deliberately carrying NO prompt and NO cwd. It is the only receipt here written outside the repository, and it is therefore the only one no reviewer of this repository will ever see.
notes: CITED AT THE LOG APPEND AND THE RELEASE, NOT AT THE ACQUISITION. `build-os/tools/specialist-handoff.sh:145` — the atomic `mkdir` — is already claimed by `tools.handoff_lock`, which classifies the fail-closed BUSY refusal, and section 22 forbids sharing the line. :122 and :166 are the two writes no existing entry classifies. The `write_scope` is the reason this record is worth having at all: it is the only mutator in the census whose durable effects land entirely outside the repository, where nothing in this repository's suite can fingerprint them.
