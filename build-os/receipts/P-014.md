## Behaviour delivered
`specialist-handoff.sh` + the `prompt-router.sh` UserPromptSubmit hook:
- **Deterministic routing** (precedence zeroize > ecc > focused, so never both): zeroization
  keywords → `zeroize`; ECC/elliptic-curve/Chrome-DevTools keywords → `ecc`; else `focused`.
- **Focused = no relaunch** (the common case; zero overhead).
- **Handoff for a disabled specialist:** (1) preserve exact original prompt + cwd, (2) activate
  ONLY the required profile via `capability-profile.sh`, (3) launch a fresh non-interactive
  `claude -p` child in the original cwd with the recursion-guard env set, (4) wait + surface
  the child's output and exit status, (5) **restore focused via an EXIT/INT/TERM trap — even on
  failure, timeout, or interruption**.
- **Guards:** recursion (`BUILD_OS_SPECIALIST_HANDOFF` env — a child never re-hands-off);
  one profile at a time (ECC/zeroize mutually exclusive); **single Serena** (profile switcher
  keeps exactly one); portable **timeout** (`timeout`/`gtimeout`/perl-alarm → 124) with an
  actionable message; **never silently succeeds** (always prints `RESULT: OK|TIMEOUT|FAILED`
  with the child exit code) and writes an **auditable receipt line** to `HANDOFF_LOG`.
- **Dry-run/status:** classifies + reports the plan with no relaunch and no profile change.
- **Integration:** the prompt-entry hook resolves the handoff script (repo-relative /
  `$CLAUDE_PROJECT_DIR` / `~/build-os`), runs detection automatically, and is non-fatal.
