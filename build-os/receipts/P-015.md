## Problem (live-install audit)
The host pulled `601272c` and ran `./install-global.sh`. The globally installed prompt hook
`~/.claude/hooks/prompt-router.sh` resolves the handoff via, in order,
`$HOOK_DIR/../../build-os/tools/specialist-handoff.sh`, `$CLAUDE_PROJECT_DIR/build-os/tools/…`,
and `$HOME/build-os/tools/specialist-handoff.sh` — for a global (no-project) install the only
viable candidate is `~/build-os/tools/specialist-handoff.sh`. But `install-global.sh` created
only `~/build-os/memory` (router sync) and **never** created `~/build-os/tools` or copied
`specialist-handoff.sh` / `capability-profile.sh`. Both were absent, so a real global-hook ECC
prompt produced only the routing reminder and performed **no handoff**. P-014's zero-touch
behaviour was proven in-repo/tests but silently broke after a global install.

## Fix
- **`install-global.sh`:** after the router sync, `mkdir -p "$USER_BUILD_OS/tools"`, copy the
  tools dir (`cp "$SRC/build-os/tools/"*.sh "$USER_BUILD_OS/tools/"`) and `chmod +x` the copies
  so executable bits are preserved. The glob mirrors the source tools dir (specialist-handoff +
  capability-profile + skill-budget-audit) and matches the installer's existing agents/commands/
  hooks copy style. An echo confirms the sync. Honors the `BUILD_OS_USER_DIR` override.
- No other installer behaviour changed; unrelated files untouched.
