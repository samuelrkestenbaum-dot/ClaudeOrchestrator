## The four fixes
1. **UserPromptSubmit dedupe without `prompt_id`** (`hook-once.sh`). The old key was
   `event-session(-prompt_id?)`; with no `prompt_id` it collapsed to session-only, so every
   prompt after the first in a session lost the reminder. New event-instance key = the
   payload's **sha256 content hash** (identical across the two duplicate global+project
   invocations of one event, different for the next event), using `prompt_id` directly when
   present. Fails open when session/payload is unidentifiable. **Regression test proves**
   duplicate invocations of one no-`prompt_id` prompt emit once, and a later prompt in the
   same session emits again.
2. **Skill-listing over budget** (`685 skills / 171824 chars > 30000`). Added an audit tool
   `build-os/tools/skill-budget-audit.sh` (ranks skills-per-plugin, flags over-budget) and a
   policy `build-os/memory/skill_budget.md` (minimal active set: keep core doc/build skills +
   the curated 9 ToB security plugins + context-mode; disable the other ~31 ToB plugins and
   mega-bundles). Tested on a fixture. **Boundary:** applying the trim + the fresh-`--debug`
   verification is a host/user step (needs the local CLI; OAuth expired).
3. **Serena policy/status honesty.** The live server is `plugin:zeroize-audit:serena`,
   plugin-bundled and launched from **unpinned git `main`** — NOT the repo's pinned bootstrap
   (`68884f1`) and NOT a pinned user-configured server. This is a **deviation** from the
   canonical pinned-preference rule; the plugin bundles Serena and the repo cannot repin it.
   Records corrected across router/current_state/residue (no false "pinned/ACTIVE" claim).
   Reproducible single-instance pin provided opt-in: `templates/serena-pinned.mcp.json`
   (commit-pinned; enable only after disabling the plugin's Serena). Live connected version
   is not independently verifiable here (CLI OAuth expired) — stated, not guessed.
4. **Remote/org vs local-verified capabilities.** The router's "Installed plugins/connectors
   (live now)" sections claimed claude.ai **org** capabilities as locally verified. Relabelled
   as **Remote / org capabilities — claude.ai (NOT in the local Claude Code plugin registry)**,
   separated from the locally-installed CLI plugins, with a **no-route-to-unverified** rule:
   confirm a capability is live in the CURRENT surface before routing.
