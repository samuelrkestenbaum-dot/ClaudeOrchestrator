# P-025 — zero-touch global bootstrap: canonical-source detection, real SHA, full guidance

Closes the last architectural gap: a **one-time-per-environment** global installer makes every
newly attached project provision itself with **no per-project command**. Suite **256 passed, 0 failed**.

## What was already true (measured, not assumed)

Re-testing the existing global path showed it *already* auto-provisioned a fresh project: the
globally-installed SessionStart hook ran `project-bootstrap.sh` against `CLAUDE_PROJECT_DIR` and
installed the runtime. So the architecture was right — but it shipped **two real defects** that
made globally-provisioned projects second-class:

1. **`source_sha: unknown`** — the global copy of the bootstrap lives at `~/build-os/tools/`, so
   its `"$HERE/../.."` resolved to the **home mirror**, which is not a git checkout. Drift
   detection was therefore dead for every globally-provisioned project.
2. **A 3-line stub `CLAUDE.md`** — `install-global.sh` never mirrored `global-claude-md.md`, so the
   managed block fell back to the `# Build OS` placeholder instead of the **56-line** canonical
   guidance. Confirmed live before the fix (3 lines vs 56).

## Fix

- **`project-bootstrap.sh` — canonical-source resolution.** When the provisional `SRC` is only the
  home mirror, resolve a genuine ClaudeOrchestrator checkout, in order: `$BUILD_OS_SOURCE` →
  the `~/build-os/.canonical-source` stamp → well-known attach locations
  (`/home/user/ClaudeOrchestrator`, `$HOME/ClaudeOrchestrator`, a sibling of the target) → the
  mirror as last resort. A candidate counts only if it has `.claude/agents/build-orchestrator.md`,
  `build-os/global-claude-md.md`, **and** `.git`. `canonical_sha()` falls back to the stamped SHA
  so the manifest is never silently `unknown`.
- **`install-global.sh`** now mirrors `global-claude-md.md` to `~/build-os/` and writes
  `~/build-os/.canonical-source` (path + real SHA + timestamp), so the global bootstrap can find
  the true checkout.
- Bonus: because a vendored project copy can now *detect* an attached checkout, its DEGRADED output
  names a **runnable** repair command instead of only "cannot self-heal".

## Live proof (this surface)

One-time `install-global.sh` → stamp `path=/home/user/ClaudeOrchestrator sha=7aef17da3710`.
Then a **brand-new project** (`git init`, one file), provisioned by the **global hook alone, with no
per-project command**: `Orchestrator: ON`; canonical SHA `7aef17da3710` **==** installed SHA;
agents **5/5**; tools **5**; `CLAUDE.md` **58 lines** (full guidance, not the stub); manifest SHA
real. A second startup reported `bootstrap: up to date (cached)` — idempotent.

## Honest boundaries

- Zero-touch requires the **one-time global install per environment/surface** — that is the platform
  constraint established in P-024 (a newly attached repo cannot make Claude Code execute its own
  hook; the platform must discover it first).
- Proven here on the Linux cloud/CCR surface. **Mac Claude Desktop is a user-side run** of the same
  one-time `install-global.sh`; I cannot execute it on that machine from this container.
- SessionStart hooks do **not** fire under `claude -p` (P-024 finding), so the end-to-end
  confirmation on any surface is a real managed/interactive session, not a `-p` run.
