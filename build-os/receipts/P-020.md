# P-020 — bootstrap registers the pinned Serena MCP (add-if-absent)

Closes the repo-addressable half of the Serena cross-surface gap the 9/10 audit named. The
SessionStart bootstrap already *installed* the Serena binary but never *registered* the
`mcpServers` entry — literally "installed but not registered." This adds an add-if-absent
registration so a surface whose `~/.claude.json` lacks Serena (e.g. a fresh Claude Cloud task)
gets a callable Serena, while a surface that already has one (the Mac's user-scope server) is
left byte-untouched. Test-first. Suite 202 → **208, 0 failed** on Linux.

## Change

- `install-accelerators.sh` (SessionStart-wired, idempotent, non-fatal) gains
  `register_pinned_serena`: it reads `CLAUDE_CONFIG_PATH` (default `~/.claude.json`) and, **only
  if no `serena` entry exists**, adds the canonical pinned server
  (`uvx --from git+…serena@68884f1… start-mcp-server --context claude-code --project-from-cwd`)
  via an atomic `os.replace`, preserving every other key. If a `serena` entry already exists it
  makes **no change** (single-server rule, P-008). A `register-serena` argument runs only this
  step (no network) for tests/targeted use; the normal run calls it after installing the binary.
- **No secret** (Serena needs no API key). **Project `.mcp.json` is untouched** (stays
  Serena-free) so nothing double-launches on the Mac's user-scope server.

## Verification (test-first)

- RED: the pre-change `install-accelerators.sh register-serena` ignored the argument and wrote
  no config.
- GREEN — new §24 (6 checks): registers when config absent; registers while preserving unrelated
  keys; leaves an existing Serena **byte-identical** (no overwrite, exactly one); repeated runs do
  not duplicate; project `.mcp.json` stays Serena-free. `bash tests/build_os_tests.sh` →
  **208 passed, 0 failed** (deterministic).
- `bash -n` clean; Python-only JSON edit (portable); atomic write; temp configs only — the real
  `~/.claude.json` is never touched by the suite.

## Boundary (honest)

- This closes the gap **iff the target surface resolves MCPs from `~/.claude.json`**. If a Claude
  Cloud task instead uses Anthropic's **managed connector/registry layer** (as the 21st.dev
  connector does — approval-gated, not bypassable by project/config files), then registering
  Serena there remains a **Cloud-environment settings** action the repo cannot perform. The
  bootstrap change is safe either way (add-if-absent, no duplicate, no secret).
- **Claude Watch** is a host **plugin** with no repo lever — enabling it in a Claude Cloud task is
  a `claude plugin` / Cloud-UI action only the user can take.

`.claude/tdd-guard/` and `.letta/` untouched. No merge/PR/deploy/secrets.
