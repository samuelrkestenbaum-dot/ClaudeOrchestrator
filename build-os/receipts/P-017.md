# P-017 — adversarial post-release correction

## Failures reproduced

- A nonzero specialist child was followed by a false “already handled” claim.
- Exit zero was treated as completion even when the child needed input.
- The full task was passed in process arguments.
- Lock cleanup recursively deleted an environment-controlled path.
- Inline routes overclaimed that disconnected or surface-absent tools were required.
- Full `SKILL.md` bodies were mislabelled as measured startup metadata cost.
- Child output was unbounded.

## Corrections

- The prompt hook now preserves the handoff exit and suppresses parent work only after
  explicit `COMPLETED`.
- Children return one of `COMPLETED`, `NEEDS_INPUT`, `BLOCKED`, or `FAILED`; missing or
  malformed status is `UNCONFIRMED` and falls back to the focused parent.
- Tasks travel over stdin, not argv. Output is bounded and visibly marked when truncated.
- Lock deletion uses validated, non-recursive `unlink` plus `rmdir`; broad unsafe paths are
  rejected. Signal traps restore focused mode and release the lock.
- Inline routes require a live availability check and name a built-in/local fallback.
- The budget report separates enabled full-body inventory from unknown runtime metadata cost.

## Verification

- `bash tests/build_os_tests.sh`: **198 passed, 0 failed**.
- Added adversarial coverage for exit-zero `NEEDS_INPUT`, child failure propagation,
  prompt argv privacy, unsafe lock overrides, availability claims, and output truncation.
- Existing untracked `.claude/tdd-guard/` and `.letta/` were preserved.
